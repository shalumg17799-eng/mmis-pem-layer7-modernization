Summary

This JCL job (PRVDAY01) performs the daily provider enrollment processing for the Medicaid Management Information System (MMIS). It enrolls new provider applications into the Provider Master file, then screens and assesses risk for unscreened providers, executing all screening and risk steps only when the enrollment step completes successfully. ### Key Functionalities: - Executes the provider enrollment program (PRVENR01) using a batch date parameter, reading daily provider applications and updating the Provider Master KSDS file, while writing any enrollment errors to a date-stamped error file with a fixed-block record length of 250 bytes. - If the enrollment step completes with a return code of 0, sorts all unscreened providers (where screening flag = 'U' in position 23) from the Provider Master file by NPI (positions 1–10, ascending) into a temporary work file for downstream processing. - Passes the sorted unscreened provider records to the provider screening program (PRVSCR01), which reads the Provider Master file and writes screening results to a date-stamped output file with a fixed-block record length of 67 bytes. - Executes the provider risk assessment program (PRVRSK01) against the Provider Master file to evaluate and assign risk levels to providers, completing the conditional processing block initiated after successful enrollment. - Runs a final cleanup/dummy step (IEFBR14) conditioned on a non-zero return code to handle any job-level wrap-up processing.

Dataset Information (6)

Dataset/Table Name Type Usage
MMPRV.PROV.APPS.D&DATE SEQUENTIAL Input file containing daily provider applications for the current batch date. Opened with OLD disposition, retained (KEEP) on both normal and abnormal termination. Read by the enrollment program PRVENR01 in STEP010.
MMPRV.PROVIDER.MASTER.KSDS VSAM_KSDS Provider Master file used as both input and output across multiple steps. Updated during enrollment (STEP010), read as sort input for unscreened providers (STEP020), and read by the screening program (STEP030) and risk assessment program (STEP040). Opened with shared disposition (SHR) in all steps.
MMPRV.PROV.ERRORS.D&DATE SEQUENTIAL Output error file created during enrollment processing (STEP010). Newly created and cataloged on normal completion; deleted on abnormal termination. Fixed-block format, record length 250 bytes, block size 25,000 bytes. Allocated with 5 primary and 2 secondary cylinders.
&&PRVSORT SEQUENTIAL Temporary work file created by the SORT step (STEP020) containing Provider Master records filtered to unscreened providers (screening flag = 'U'), sorted by NPI (positions 1–10) in ascending order. Passed to the next step and deleted on abnormal termination. Allocated with 20 primary and 5 secondary cylinders.
MMPRV.SCREEN.RESULTS.D&DATE SEQUENTIAL Output file produced by the provider screening program PRVSCR01 in STEP030. Newly created and cataloged on normal completion; deleted on abnormal termination. Fixed-block format, record length 67 bytes, block size 6,700 bytes. Allocated with 10 primary and 5 secondary cylinders.
MMPRV.PROD.LOADLIB PDS Load library containing executable program modules (PRVENR01, PRVSCR01, PRVRSK01) used across all steps. Referenced at both the job level (JOBLIB) and step level (STEPLIB) with shared disposition.

Business Rules

Supporting Code

//STEP010 EXEC PGM=PRVENR01, // PARM='BATCH_ID=&BATCH_DATE' ← Batch date passed to identify daily application batch //APPINPUT DD DSN=MMPRV.PROV.APPS.D&DATE, ← Daily provider applications input file (date-stamped) // DISP=(OLD,KEEP,KEEP), ← Pre-existing file; always retained regardless of outcome //PRVMSTR DD DSN=MMPRV.PROVIDER.MASTER.KSDS, ← Provider Master File; updated with enrolled providers // DISP=SHR ← Shared access for read and in-place update //APPERROR DD DSN=MMPRV.PROV.ERRORS.D&DATE, ← Date-stamped error file for rejected applications // DISP=(NEW,CATLG,DELETE), ← Catalogued on success; DELETED on failure // DCB=(RECFM=FB,LRECL=250,BLKSIZE=25000) ← Fixed 250-byte records per rejected application // IF (STEP010.RC = 0) THEN ← Gateway: downstream steps only run on full success
