Summary

This JCL job (PRVMTH01) performs month-end provider processing by executing three steps: generating a provider revalidation queue, extracting provider data for T-MSIS (Transformed Medicaid Statistical Information System) reporting, and archiving the T-MSIS output to tape for long-term retention. ### Key Functionalities: - Reads the Provider Master KSDS file to identify providers requiring revalidation and writes the results to a new date-stamped Revalidation Queue file (80-byte fixed-block records, 5 cylinders primary space). - Reads the Provider Master KSDS file again to extract provider information for T-MSIS state reporting and writes the output to a new date-stamped T-MSIS Provider file (120-byte fixed-block records, 20 cylinders primary space). - Copies the T-MSIS Provider output file to the next generation of a tape-based GDG archive dataset (MMPRV.TMSIS.ARCHIVE +1) for long-term storage using standard tape labeling.

Dataset Information (5)

Dataset/Table Name Type Usage
MMPRV.PROVIDER.MASTER.KSDS VSAM_KSDS Input - Read shared (SHR) in both STEP010 and STEP020 as the primary provider master reference file; existing cataloged dataset, no modifications made
MMPRV.REVAL.QUEUE.D&DATE SEQUENTIAL Output - Newly created and cataloged date-stamped revalidation queue file written by STEP010; deleted if step fails; fixed-block records of 80 bytes, block size 8000, allocated 5 cylinders primary and 2 cylinders secondary on disk
MMPRV.TMSIS.PROVIDER.D&DATE SEQUENTIAL Output in STEP020, Input in STEP030 - Newly created and cataloged date-stamped T-MSIS provider extract file written by STEP020 and read by STEP030 for archiving; deleted if STEP020 fails; fixed-block records of 120 bytes, block size 12000, allocated 20 cylinders primary and 5 cylinders secondary on disk
MMPRV.TMSIS.ARCHIVE(+1) GDG Output - New generation of the T-MSIS archive GDG written to tape in STEP030 via IEBGENER copy; cataloged on success, deleted if step fails; standard tape label, generation +1 created as archive copy of the T-MSIS provider extract
MMPRV.PROD.LOADLIB PDS Input - Job-level load library referenced via JOBLIB to provide executable program modules (PRVREV01, PRVTMS01) for all steps in the job; shared access

Step 2 - STEP020 - TMSIS Provider Data Extract for Federal Medicaid Reporting

Business Rules

Supporting Code

| Code Line | Business Significance | |-----------|----------------------| | `//STEP020 EXEC PGM=PRVTMS01` | Invokes the TMSIS Provider Extract program as part of month-end provider processing | | `//PRVMSTR DD DSN=MMPRV.PROVIDER.MASTER.KSDS,DISP=SHR` | Reads the Provider Master File as the single source of all provider data for the TMSIS extract; shared access allows concurrent use by other processes | | `//TMSISOUT DD DSN=MMPRV.TMSIS.PROVIDER.D&DATE` | Creates a uniquely date-stamped TMSIS Provider Extract output file — one file per execution date, ensuring traceability of each month-end reporting run | | `DISP=(NEW,CATLG,DELETE)` | Business retention rule — the TMSIS extract file is permanently cataloged and available for downstream use only upon successful completion; automatically deleted on failure to prevent incomplete federal reporting data from persisting |

Step 3 - STEP030 - Archive TMSIS Provider Extract to Tape

Business Rules

Supporting Code

| Rule | JCL Code Lines | Business Meaning | |------|---------------|-----------------| | Source file is the current date's TMSIS Provider Extract | `//SYSUT1 DD DSN=MMPRV.TMSIS.PROVIDER.D&DATE,DISP=SHR` | The TMSIS extract produced for today's processing date is the input to be archived | | Target is a new versioned generation of the TMSIS Archive on tape | `//SYSUT2 DD DSN=MMPRV.TMSIS.ARCHIVE(+1), UNIT=TAPE` | Each month-end run creates a new (+1) archive generation on tape, preserving all prior generations | | No transformation — exact copy only | `//SYSIN DD DUMMY` | SYSIN=DUMMY means no copy instructions are provided; all records are copied exactly as-is with zero modification | | Tape archive uses standard label as first file on tape | `LABEL=(1,SL)` | The archive is written as the first file on the tape with a standard label for proper tape management | | Catalog on success, delete on failure | `DISP=(NEW,CATLG,DELETE)` | If archival succeeds, the new generation is cataloged and retained; if it fails, the incomplete generation is automatically deleted |
