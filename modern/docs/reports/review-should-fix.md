## review:sanctions-service:0 (verdict APPROVE)

- ProviderServiceClient.java:56 with kit ServiceClients.java:87: a 404 from the token endpoint (for example an unknown Keycloak realm) is thrown inside the interceptor as HttpClientErrorException.NotFound and treated as NOT_FOUND. - SanctionIntake.java:154 (also :114, :121, :156): when saving the counts after record n fails, the reason is only 'ERROR: ...' and does not name record n or its NPI (RUN_COUNTS log shows this). Add a prefix such as 'counts after record n could not be saved: ' and 'completion could not be saved: '.
- SanctionIntake.java:147,151: runs.counts runs before couldNotApply is thrown. If counts also fails (database down), the original cause and the record name are lost. Build the RunFailure first, then try counts and addSuppressed any failure, then throw.
- PIT on application.*: 6 SURVIVED and 6 NO_COVERAGE, all in SanctionIntake.reasonOf/isDatabaseError (:202-221). Negating :206, which lets raw SQL through, survives PIT; only the integration test catches it. Add unit tests: DataAccessException with SQL, SQLException in the chain, multi-line, over 200 chars, null message.
- ReviewFixesTest.java:42: the 1 s provider limit covers all 6 classes in that context, so every normal provider call there has a 1 s budget. The rerun was green with about 420 MB free and showed no spurious timeout. To lower flake risk, limit 1 s to the two timeout classes, or use 2 s with a 6 s delay (Q-097 C, additive).
- JdbcSanctionIntakeRuns.java:52-58: link() ignores the update count, and if the sub-select finds no run it sets intake_run_id to NULL without error, so a re-run would apply the record again. Require exactly 1 row with a non-null run id, otherwise throw (this rolls back the record).

- ServiceClients.java:45: the public Supplier<RestClient.Builder> constructor builds clients with no limits, so the MUST-FIX 3 guarantee can be bypassed. Make it package-private or test-only, or require the builder to carry timeouts.
- SanctionIntake.java:205-208: reasons that are not database errors are not cut to 200 characters (only to 500 by JdbcSanctionIntakeRuns:99) and can span several lines. Apply the same first-line, 200-character rule to every reason so BatchRun.error is uniform.
- SanctionIntakeJobConfig.java:79: if the executor has shut down, TaskExecutorJobLauncher swallows TaskRejectedException and never calls the listener. The run stays RUNNING and its file stays in the files map. Add this to the recorded item 'RUNNING runs after a restart not swept'.

## review:risk-service and service-kit:0 (verdict MUST-FIX)

- AssessRisk.java:48 increments pem.risk.tiers.assigned inside the transaction, before commit. A failed commit followed by a redelivery counts the same event twice (AC-8). Increment in TransactionSynchronization.afterCommit.
- ScreeningEventsListener.java:47: path(..).asText() turns JSON null into the text "null", which is then stored and announced as the taxonomy. The subject is not checked against ^[0-9]{10}$, and a taxonomy over 10 chars hits CHAR(10) and is retried, then sent to the DLT. Validate first and send malformed events straight to the DLT without retries.
- risk-service has no explicit DataAccessException handling on REST. A database outage gets Boot's /error JSON 500 instead of a problem+json 503 like provider-service. It contains no SQL text and is logged, but it is not the explicit handling D-024 asks for.
- Kit ProblemHandler precedence works today but only implicitly. All 5 service advices (Gateway, Directory, Request, Provider, Tmsis) are component-scanned, so they register before the auto-configured bean, and the advice sort is stable. Their @Order(LOWEST_PRECEDENCE) equals the kit's, so it adds nothing. Give service advices a higher order explicitly.
- BearerProblemHandler.java:39/:47 write a fixed 401/403 body. If a service ever enables query or form bearer tokens, Spring's 400 invalid_request would carry a body saying 401. Build the body from response.getStatus() and skip the write when response.isCommitted().
- PemKitProperties.Client accepts a zero or negative pem.client.read-timeout or connect-timeout. A zero read timeout breaks every call at runtime, not at startup. Validate that both durations are positive when the properties are bound.
- Kit CorrelationId.SAFE accepts any 1-64 character token, but events.yaml declares correlationId as format uuid. This drifts from the contract in every service. Align either the contract or the sanitizer.
- Bookkeeping to finish before closing: MAM-38 and MAM-41 have no trace.json, and builtCommit/testsSha256 are empty in their specs. The MAM-26 spec testsSha256 is stale (9fc4035a vs 52feabfc) and MAM-29's is empty.
- MAM-35 AC-8 says the failure goes to the JSON log, but the tests run with PEM_LOG_FORMAT= (plain text), so the ECS line is never checked. Add one assertion that runs with the ecs format.
- Q-116 side effect: if the database time zone is behind UTC, a PUT answers 200 with version N+1 while GET still returns N, and every further PUT gets 422 until the database date catches up. Option B (select with the Clock's date) avoids this.
- The application layer carries HTTP concerns: ApiException with HttpStatus in ManageRiskRules and AssessOnRequest, and @JsonInclude on AssessOnRequest.Assessment. Move the HTTP mapping to the api package.
- WWW-Authenticate keeps Spring's error_description (for example 'Jwt expired at ...'). This is standard under RFC 6750, but it reveals why the decoder rejected the token. Consider leaving the description out.
- MAM-38 and MAM-41 tests were written after the code (FINAL PLAN Part D), so they had no red phase. That they are not vacuous rests on PIT (41/41 mutants killed) and the Lane 3 notes.

- ScreeningEventsListener.java:45: the branch for event types other than ScreeningCompleted is untested (JaCoCo partial branch). Add a test: such an event is marked processed and publishes nothing.
- Authorisation order: a PROVIDER sending an unreadable body to PUT /risk-rules gets 400, not 403, because the body is read before @PreAuthorize. Same item as in the directory review; record it for the final report.
- Housekeeping for the lead: specs/MAM-35.md testsSha256 is still c52765...; the hash file is now 03c8b6... after the new ScreeningEventsCorrelationIdTest. MAM-38 and MAM-41 builtCommit/testsSha256 are still empty.
