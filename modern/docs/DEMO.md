# PEM demo: journey J1, a provider enrols and is approved

The legacy PEM batch flow (PRVENR01 → PRVSCR01 → PRVRSK01, then an analyst decision and the directory and notice
programs) is shown running as Java 21 / Spring Boot services behind a React portal and console. Everything below runs on
this machine in Docker Compose project `pem`. All data is synthetic.

## 1. Before the audience arrives (5 minutes)

From `modern/` in Git Bash:

```bash
./pem.sh up      # builds the jar and the web UI, starts the stack, waits until every container is healthy
./pem.sh seed    # loads the 16 seeded providers and empties the journey tables and the Mailpit inbox
./pem.sh ps      # every container shows (healthy)
```

Optional dress rehearsal (about 30 seconds per run, then seed again so the demo starts clean). The automated journey
J1 passed 2 of 2 and then 3 of 3 runs on 2026-11-19, each from a fresh seed, with zero axe violations on every page,
and passed again (with J2 to J5) on the polished screens on 2026-11-19 at 19:30:

```bash
./pem.sh j1 && ./pem.sh seed
```

Open the demo browser like this (Windows, from `cmd` or the Run box). On this machine "localhost" first resolves to
`::1`, where WSL's relay (not Docker) listens and now and then resets connections; the flag sends "localhost" to
127.0.0.1 for this browser window only, and the separate profile makes sure the flag is applied:

```bat
start chrome --user-data-dir=%TEMP%\pem-demo --host-resolver-rules="MAP localhost 127.0.0.1" http://localhost:5173
```

| What | URL |
|---|---|
| Web UI (portal and console) | http://localhost:5173 |
| Public provider directory | http://localhost:5173/directory |
| API gateway | http://localhost:8080 |
| Swagger UI per service | http://localhost:18081/swagger-ui.html (provider), 8082 (enrollment) to 8089 (tmsis) |
| Keycloak (realm `pem`) | http://localhost:8180 |
| Mailpit (notices sent) | http://localhost:8025 |

Users: `provider1` (PROVIDER, NPI 1003000111), `analyst1` (ANALYST), `supervisor1`, `admin1`. The passwords are in
`modern/infra/.env.local` (generated by `./pem.sh up`, git-ignored). Open it yourself; never paste it on screen.

Use two windows of that browser: a normal one for provider1 and a private one (Ctrl+Shift+N) for analyst1.

## 2. Click by click

Screenshots of every step below (taken on the live stack, 2026-11-19): `modern/docs/reports/ui-screenshots/01-...` to
`11-...png`; J6 and J7 are `12-...` to `14-...png`, every other screen `20-...` to `32-...png`. Every page shows the menu
on one line, a breadcrumb ("Home > ...") under it and a one-line description under its title. Statuses and results read
in plain words with the legacy code in brackets ("Pending (P)", "Pass (P)"); the four screening sources are named
**Licence board**, **OIG exclusion list (LEIE)**, **SAM.gov debarment** and **SSA death records**; record details are
shown as label/value lists, not tables.

**Step 1. The provider applies (legacy PRVENR01 + APPINPUT feed).** Screens 01-03.
1. Window 1: open http://localhost:5173 and choose **Sign in**. Keycloak opens: sign in as `provider1`.
2. **My enrolment** opens with the card **Your enrolment**: no application yet, the next step in plain words and the
   **Apply for enrolment** button. Choose it.
3. The form is in sections (Provider, then Individual details); every field has a hint with an example. Provider type
   **Individual (IN)**, NPI `1003000111`, Medicaid ID `TX0000111`, Taxonomy code `207Q00000X`, Last name `RIVERA`,
   First name `MARIA`, Licence number `MD12345`, Licence state `TX`. The box **Review your answers** above the button
   shows what will be sent.
   Say: the provider may apply only under the NPI of their own login (Q-095); anything else is refused with 403.
4. Choose **Submit application** (one click). **Application status** opens with the line **Reference: <id>** under the
   title, the green box **Application received** with what happens next, then a step indicator Submitted, Validated,
   Screened, Risk assessed, Approved with the current step highlighted ("3 of 5 Waiting for screening"), and the
   application with the status badge **Validated** and the date in plain form ("Submitted 19 Nov 2026"; every screen
   shows dates this way, while date fields you type into keep MM/DD/YYYY). Reload a few seconds
   later to see the steps move on. (A rejected application shows step 2 as "Validation failed": journey J2.)
   Say: the legacy loader stopped at the first bad record and wrote it anyway; here every check runs, once each (D-001).

**Step 2. Screening and risk tier run on their own (legacy PRVSCR01 and PRVRSK01, now event driven).**
Nothing to click. Within a few seconds the provider is registered Pending/Unscreened, screened against the four mocked
sources (licence board, OIG LEIE, SAM.gov, SSA death master file, all through WireMock) and given risk tier **Limited (L)**
from taxonomy prefix 207. See section 3 for how that rule traces back to the COBOL.

**Step 3. The analyst approves (legacy: no program ever set ACTIVE except PRVSAN01; D-019).** Screens 04-07.
1. Window 2 (private): open http://localhost:5173/console/queues and sign in as `analyst1`.
2. **Work queues**: the tiles at the top count each queue. 1003000111 is under **Pending approval** (screened Pass).
   Choose **Review**. (The provider detail page, via **Provider search**, shows the same provider with **Status: Pending
   (P)**, the badges **Screening result: Pass (P)** and **Risk tier: Limited (L)**, the provider record, and the
   Screening, Sanctions, Revalidation and Notices panels.)
3. **Approve or deny**: the page opens with the box **In short**: "RIVERA MARIA, NPI 1003000111, Pending (P)", "All 4
   checks passed: Licence board, OIG exclusion list (LEIE), SAM.gov debarment, SSA death records" and "Risk tier Limited
   (L): set from the first three characters of the taxonomy code (207Q00000X -> 207)". Below it the **Screening
   results** table gives each source's detail ("Licence active until Sep 2028", "Not excluded", "Not debarred", "Not
   deceased"), then the decision; the provider's details follow under the button. The line above the button
   reads "No decision chosen yet. Nothing is sent until you choose Record decision." Choose **Approve (becomes
   Active)**: it now reads "You are about to approve ...". Choose **Record decision**.
4. The confirmation reads **Decision recorded. Status: Active (A). Revalidation due:** five years from today (D-003; the

**Step 4. The provider is in the public directory (legacy PRVDIR01 flat file, never scheduled).** Screen 08.

## 4. If something goes wrong

| Symptom | Do this |
|---|---|
| The browser shows `ERR_CONNECTION_RESET` or a page hangs on "Searching" / "Loading" | Reload the page. If it repeats, the browser was not started with the flag in section 1: close it and start it with that command (cause: `localhost` -> `::1` -> WSL's `wslrelay`) |
| A page says the service is not available, or a container is not healthy | `./pem.sh ps`; then `docker compose -p pem --env-file infra/.env.local -f infra/docker-compose.yml --profile apps restart <service>` (only project `pem`). The 10 apps share `pem-apps`; it takes about 2 minutes to come back |
| The application stays Validated but the provider never shows Pending or screened | Kafka lost its consumer groups. Restart it: `docker compose -p pem --env-file infra/.env.local -f infra/docker-compose.yml restart kafka`, wait 30 s, then `./pem.sh seed` and start the journey again |
| Submitting says an application for this NPI was already accepted (E103) | The demo was run before without a reseed: `./pem.sh seed` |
| Keycloak sign-in loops or says the session expired | Close the browser window (or use a new private one) and sign in again |
| Mailpit shows nothing | Check http://localhost:8025 is up (`./pem.sh ps`); the notice follows the approval within a few seconds; `./pem.sh seed` empties the inbox, so do not seed after approving |
| The whole stack is stuck | `./pem.sh down`, `./pem.sh up`, `./pem.sh seed` (about 5 minutes; data volumes are kept) |
| Memory is short (other projects are running) | `docker stats --no-stream`; PEM needs about 1.2 GiB used, 2.5 GiB at its limits. Do not stop other projects' containers |
| Port already in use on `./pem.sh up` | The message names the port; free it or set `PEM_PG_HOST_PORT` / `PEM_PROVIDER_HOST_PORT` |
| Back-up plan without the browser | `bash tools/checks/smoke-journey-j1.sh` runs the same journey through the API and prints PASS per step |
